JAX / JAXLIB / EQUINOX JOBS
==========================

Quick start (rents a GPU, installs CUDA dependencies, verifies the GPU,
runs a small training example, collects outputs, and destroys the GPU):

  python /home/jump/vast-tools/job.py --timeout-seconds 180

Run your own standalone Python script:

  python /home/jump/vast-tools/job.py --job /absolute/path/train.py \
    --timeout-seconds 3600 --max-hourly 0.60 -- --steps 1000

Additional packages (resolved together with the pinned base requirements):

  python /home/jump/vast-tools/job.py --job /absolute/path/train.py \
    --requirements /absolute/path/extra-requirements.txt

Search without creating or billing an instance:

  python /home/jump/vast-tools/job.py --search-only

Environment:
  - Proven pytorch/pytorch:2.5.1-cuda12.4-cudnn9-runtime container for SSH.
    uv installs Python 3.12 into an isolated /opt/jax virtual environment;
    uv manages Python and all packages; the job uses CUDA 13 wheels,
    independent of the image toolkit. uv is installed with its standalone
    installer (version 0.13.1); pip is never invoked or seeded.
  - requirements-jax.txt pins JAX 0.11.2, jaxlib 0.11.2, Equinox 0.13.8.
  - jax[cuda13] installs NVIDIA CUDA libraries through uv; no local CUDA
    toolkit install is required. Offers must report CUDA 13 capability.
  - JAX_PLATFORMS=cuda forces a GPU backend; CPU fallback fails the run.
  - LD_LIBRARY_PATH is unset to avoid overriding the installed CUDA libraries.
  - JAX GPU memory preallocation is disabled. Jobs may change that policy.
  - A preflight performs real JIT compilation and Equinox gradient updates
    and asserts that training loss decreases on the RTX 4090.

Job interface:
  - Only the selected Python file and explicit requirements are uploaded.
    Project folders, local imports, datasets, and credentials are not
    automatically transferred. Package your code or fetch data in the job.
  - Remote working directory: /workspace/job.
  - Write all results/checkpoints under JOB_OUTPUT_DIR, which is
    /workspace/job/outputs. Outputs elsewhere are not collected.
  - Job arguments follow -- and are passed as literal arguments.
  - Preflight artifacts go in outputs/preflight/. User-job artifacts go
    under outputs/, so the preflight does not overwrite user results.
  - Never put API tokens into your script or requirements file. The Vast
    API key and SSH private key remain on this server.

Results on this Hetzner server:
  /home/jump/vast-tools/runs/<UTC timestamp>-<random suffix>/
    console.log      setup, verification, and user-job stdout/stderr
    metadata.json    image, input path, instance label/offer, SSH endpoint
    outputs/         incremental local mirror of remote outputs
    sync.log         transfer diagnostics
    sync-status.json time of the most recent completed transfer
    artifacts.json   final file inventory, sizes, SHA-256 hashes

outputs/ includes environment.txt (uv freeze), requirements.lock (fully
resolved dependencies), nvidia-smi.txt, uv-version.txt, and gpu.csv with
GPU utilization, memory usage, temperature, and power sampled every 5s.

Metrics and checkpoint collection:
  - JOB_METRICS_DIR=/workspace/job/outputs/metrics
  - JOB_CHECKPOINT_DIR=/workspace/job/outputs/checkpoints
  - The launcher uses incremental rsync every 30s during execution,
    then a final sync (up to 3 attempts) before destroying the instance.
    --sync-interval 10 requests more frequent collection (minimum 10s).
    --sync-timeout-seconds 600 allows up to 10 minutes per transfer for
    large checkpoints; the default is 300 seconds per transfer. Transfers
    fail after 60 seconds without network activity and are retried later.
  - Local files are immediately available in runs/<run>/outputs/metrics/
    and runs/<run>/outputs/checkpoints/ while the job is running.
  - A successful final transfer is recorded in sync-status.json. SHA-256
    hashes and byte sizes of fetched files are recorded in artifacts.json.
  - No --delete is used: checkpoints already fetched remain locally even
    when the job later rotates or deletes its remote checkpoints.
  - Remote files must be closed/renamed atomically before they count as
    complete checkpoints. Write a name containing .tmp and os.replace it
    to the final name; *.tmp* is excluded from transfers. The example does
    this for four numbered .eqx checkpoints and flushes metrics as JSONL.
  - Batch metric writers must flush/close their files; unflushed memory
    buffers cannot be fetched. A JSONL file can end in a partial line
    during a live transfer; parse complete lines until the final sync.
  - --require-artifact 'metrics/*.jsonl' --require-artifact 'checkpoints/*.eqx'
    makes the launcher fail if expected files were not retrieved. Patterns
    are relative to outputs/. The bundled example requires its final
    checkpoint and metrics file automatically.
  - This retrieves files; it does not pull data from external W&B/TensorBoard
    services unless your job also writes local files under outputs/.
  - Local/remote rsync is required. This Hetzner host already has rsync;
    remote setup installs rsync and curl through apt, then uses uv only
    for Python environments, dependency resolution, and installation.

Example custom invocation with required metrics and checkpoints:

  python /home/jump/vast-tools/job.py --job /absolute/path/train.py \
    --sync-interval 30 --require-artifact 'metrics/*.jsonl' \
    --require-artifact 'checkpoints/*.eqx' -- --steps 1000

Limits and cleanup:
  - Defaults: one RTX 4090, 40 GB disk, USD 0.60 listed hourly price cap,
    10 minutes to become SSH-ready, 15 minutes for installation, 30 minutes
    for verification plus the user job, up to 3 final download attempts (5 minutes each by default).
  - Jobs select hosts advertising >=500 Mbps downloads to reduce setup
    delays. --boot-timeout-seconds changes the default 10-minute boot wait.
  - --timeout-seconds changes the verification + user-job runtime limit.
    It does not include installation or boot time. --disk must be >=30 GB.
  - The watchdog is adjusted to boot + setup + job + one in-progress transfer + three final transfer attempts + margin;
    the old smoke test's 10-minute timer is not used for longer jobs.
  - Live stdout/stderr is saved to console.log; inspect that file during
    a running job. The parent prints its tail after successful completion.
  - Even on job/setup failure, output retrieval is attempted before cleanup.
    Failed retrieval is reported; destruction still proceeds and any
    uncollected instance data is lost. Important jobs should also upload
    checkpoints to durable storage themselves.
  - Only one managed run may be active at once (shared active.json).
  - Emergency cleanup: python /home/jump/vast-tools/smoke.py --cleanup
    Or destroy the instance with the saved label in the Vast.ai console.
  - Cleanup is verified via the API. If it cannot be verified, active.json
    is retained for retry. The local watchdog requires this server to stay
    running and connected. Billing includes boot/setup/download time;
    bandwidth can cost extra, so the hourly cap is not a total-spend cap.

Maintenance:
  Update requirements-jax.txt deliberately, then rerun the example job on
  a real GPU before using new versions for longer jobs. Each run records
  its full resolved package versions in outputs/environment.txt and a
  resolved requirements.lock generated by uv pip compile and installed
  with uv pip sync. The uv pip namespace is uv itself; it does not run pip.
  No instance is intentionally kept idle between jobs.
